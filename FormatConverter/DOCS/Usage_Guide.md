# Руководство по сценариям использования (Usage Guide)

**Проект:** DataBridge — Конвертер и валидатор данных  
**Версия:** 1.0.0

---

## 1. Быстрый старт

Утилиту можно запускать:
1. Как команду CLI: `databridge <команда> [параметры]`
2. Как модуль Python: `python -m databridge <команда> [параметры]`
3. Через корневой скрипт: `python FormatConverter.py <команда> [параметры]`

---

## 2. Основные сценарии использования

### Сценарий 1: Конвертация CSV в JSON с валидацией и фильтрацией ошибок

**Задача:** Получен «грязный» файл выгрузки `samples/invalid.csv`. Необходимо проверить его по схеме `samples/schema.yaml`, сохранить корректные записи в `output.json`, ошибочные — в `errors.csv`, и сгенерировать наглядный `report.html`.

**Команда:**
```bash
databridge convert samples/invalid.csv --to json --config samples/schema.yaml --output output.json --errors errors.csv --report report.html
```

**Вывод в консоли:**
```text
Всего записей: 12
Успешно обработано: 1
Ошибок: 11
  - Строка 2: поле "email" не соответствует формату
  - Строка 3: поле "age" вне диапазона (200 > max 100)
  - Строка 4: поле "name" обязательное поле отсутствует или пусто
  - Строка 5: поле "age" не является целым числом (integer): 'abc'
  - Строка 6: поле "id" значение '1' не уникально (уже встречалось ранее)
  - Строка 7: поле "name" длина строки (1) меньше минимальной (2)
  - Строка 8: поле "birth_date" не соответствует формату даты (ожидался формат YYYY-MM-DD): '99-99-9999'
  - Строка 9: поле "id" обязательное поле отсутствует или пусто
  - Строка 10: поле "age" меньше минимума (16)
  - Строка 11: поле "email" обязательное поле отсутствует или пусто
  - Строка 12: поле "email" не соответствует формату
Результат сохранён: output.json
Ошибки сохранены: errors.csv
Отчёт сохранён: report.html
```

**Результат:**
1. `output.json` содержит только валидную запись:
```json
[
  {
    "id": 1,
    "name": "Иван",
    "contact_email": "ivan@mail.ru",
    "age": 25,
    "birthday": "1999-01-15"
  }
]
```
2. `errors.csv` содержит все 11 ошибочных строк с указанием номера строки и описания ошибки.
3. `report.html` сформирован для руководства и аудита качества данных.

### Сценарий 2: Валидация существующего JSON без конвертации

**Задача:** Проверить входящий JSON-файл перед отправкой во внутренний сервис без создания нового файла данных.

**Команда:**
```bash
databridge validate samples/input.json --config samples/schema.json --report report_json.html
```

Если в файле есть ошибки, утилита завершится с ненулевым кодом выхода `1`, что позволяет использовать её в CI/CD пайплайнах и bash-скриптах автоматизации.

### Сценарий 3: Аналитика структуры и профилирование файла (`stats`)

**Задача:** Экспресс-анализ неизвестного датасета перед созданием схемы валидации.

**Команда:**
```bash
databridge stats samples/valid.csv
```

**Вывод:**
```text
=================================================================
СТАТИСТИКА ФАЙЛА: samples/valid.csv
=================================================================
Размер файла:        0.41 КБ
Всего записей:       10

-----------------------------------------------------------------

-----------------------------------------------------------------
id                 | integer  | 10/10      | 0        | 10        
name               | string   | 10/10      | 0        | 10        
email              | string   | 10/10      | 0        | 10        
age                | integer  | 10/10      | 0        | 10        
birth_date         | date     | 10/10      | 0        | 10        
=================================================================
```

### Сценарий 4: Конвертация XML в Excel (.xlsx)

**Задача:** Преобразовать выгрузку `samples/input.xml` в электронную таблицу Excel.

**Команда:**
```bash
databridge convert samples/input.xml --to excel --output result.xlsx
```

**Результат:** Создаётся стилизованный Excel-файл со сформированными заголовками синего цвета и автоподбором ширины столбцов.

---

### Сценарий 5: Чтение CSV с нестандартным разделителем (точка с запятой)

```bash
databridge convert input_semicolon.csv --delimiter ";" --to json --output result.json
```
