## 2. Результаты по модулям

### 2.1. Модуль `readers` (`tests/test_readers.py`)
- **CSVReader**:
  - Успешно проверено чтение стандартного CSV с заголовками;
  - Проверено чтение файла без заголовков (`has_headers=False`) с генерацией суррогатных имен колонок `col_1`, `col_2`;
  - Проверена работа с кастомными разделителями (точка с запятой `;`, табуляция `\t`);
  - Проверено автоматическое определение кодировок (UTF-8, UTF-8-BOM, CP1251).
- **JSONReader**:
  - Проверена сериализация плоских массивов объектов;
  - Проверена распаковка вложенных структур с ключами верхнего уровня (`items`, `data`);
  - Проверен перехват синтаксических ошибок JSON с выводом номера строки и столбца.
- **XMLReader**:
  - Проверено извлечение элементов плоских XML-документов;
  - Проверена комбинированная обработка атрибутов и дочерних тегов.
- **ExcelReader**:
  - Проверено чтение ячеек разных типов (числа, даты, строки) с активного листа и листа по имени.
- **Factory & Error Handling**:
  - Корректная генерация `ReaderError` при обращении к несуществующему файлу или директории без прав.

### 2.2. Модуль `validators` (`tests/test_validators.py`)
- Проверена работа всех типов правил:
  - `required`: фиксация пропусков, `None`, пустых пробельных строк;
  - `type`: целые числа (строгий отсев дробей), числа с плавающей точкой (с `.` и `,`), даты по маске, булевы значения;
  - `range`: граничные условия `min`/`max` для чисел и календарных дат;
  - `pattern`: валидация RegEx (почтовые адреса);
  - `unique`: пакетный контроль дубликатов по ключу;
  - `length`: границы минимальной и максимальной длины текстовых полей.

### 2.3. Модуль `converters` (`tests/test_transformers.py`, `tests/test_pipeline.py`)
- Проверена работа цепочки трансформаций: `strip` -> `capitalize` -> `lower` -> `replace_map`;
- Проверено преобразование Unix timestamp в ISO дату;
- Проверен маппинг полей (`mapping` и `alias`);
- Проверена изоляция ошибочных строк: только валидные попадают в целевой файл, невалидные сохраняются в `errors.csv` с деталями ошибок.

### 2.4. Модуль `reporters` и `cli` (`tests/test_cli.py`)
- Проверена генерация автономного HTML-отчета;
- Проверена работа команд CLI: `convert`, `validate`, `stats`;
- Проверены коды возврата (0 при успехе, 1 при наличии ошибок или сбое).

## 3. Протестированные граничные случаи (Edge Cases)

1. **Пустой файл** — не приводит к падению, возвращает пустой список записей с корректным отчетом.
2. **Файл только с заголовками** — корректно обрабатывается как 0 записей.
3. **Строка с пробелами** — правило `required` отклоняет значение `"   "` как пустое.
4. **Регистронезависимость булевых полей** — значения `"True"`, `"TRUE"`, `"true"`, `"да"`, `"1"` валидируются эквивалентно.
5. **Большие числа и отрицательные значения** — корректно парсятся числовыми валидаторами.
6. **Ошибки кодировок Windows (CP1251)** — утилита автоматически пробует альтернативные кодировки, предотвращая сбой `UnicodeDecodeError`.
7. **Дублирование имен колонок в CSV** — автоматическая уникализация (`id`, `id_2`).

## 4. Статус дефектов

| ID дефекта | Описание проблемы | Статус | Решение |
|---|---|---|---|
| **DEF-01** | При конвертации чисел в JSON значения сохранялись как строки | **Исправлено** | Добавлено автоматическое приведение типов `cast_types=True` в конвейере |

| **DEF-03** | Внутреннее поле `_row_number` попадало в результирующий файл | **Исправлено** | Метод `clean_records` фильтрует служебные поля с префиксом `_` |
