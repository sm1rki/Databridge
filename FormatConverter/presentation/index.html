Проблема
Проблема обработки разнородных данных

"Зоопарк" форматов

Данные поступают в несвязанных видах: CSV от операторов, JSON с веб-форм, XML из госсистем и Excel (.xlsx) от пользователей.

Ошибки в данных

Человеческий фактор: невалидные e-mail, пропуски обязательных полей, дубликаты ID, неверные форматы дат, выход чисел за границы.

Сложности импорта

Падение систем импорта из-за несоответствия типов, необходимость чистить файлы вручную часами.

Решение DataBridge: Консольный инструмент (CLI) без базы данных, автоматизирующий полный цикл: Чтение → Валидация → Фильтрация → Трансформация → Конвертация → Отчёт.

Функционал
Ключевые возможности системы (MVP)

Чтение и запись (4 формата)

  • CSV: автоопределение разделителей, поддержка файлов без заголовков, кодировки CP1251/UTF-8.
  • JSON: массивы объектов и корневые обёртки.
  • XML: плоские деревья списков записей.
  • Excel (.xlsx): чтение и стилизованная запись.

Валидация и трансформация

  • Декларативные схемы правил (YAML / JSON).
  • Проверка обязательности, типов, диапазонов, RegEx, уникальности, длины строки.
  • Маппинг (переименование) полей.
  • 7 типов трансформаций (регистр, trim, словарь, даты).
  • Изоляция ошибок в errors.csv и наглядный HTML-отчёт.

Архитектура
Модульная архитектура (Pipeline Pattern)

1. Readers

BaseReader, CSVReader, JSONReader, XMLReader, ExcelReader, Factory.

2. Validators

ValidationEngine, типизированные правила (rules.py), модели (models.py).

3. Converters

ConversionPipeline, FieldMapper, библиотека функций transformers.py.

4. Reporters

ConsoleReporter, автономный HTMLReporter, StatsReporter.

Архитектурные принципы

Слабая связанность модулей (Low Coupling), принцип открытости/закрытости (Open/Closed SOLID) — добавление нового формата не требует модификации ядра валидации и трансформаций.

Модули I/O
Подсистема чтения и записи данных

Особенности подсистемы Readers

  • Единый контракт: read(path) -> List[Dict].
  • Каждая запись обогащается исходным номером строки _row_number для точной локализации ошибок.
  • Автоопределение разделителей CSV (запятая, точка с запятой, табуляция).
  • Безопасная обработка кодировок: перебор UTF-8, UTF-8-sig, CP1251.

Особенности подсистемы Writers

  • Единый контракт: write(records, path).
  • Метод clean_records() удаляет внутренние метаполя (_row_number, _errors).
  • В Excel-файлах создаётся форматированная «шапка» с автоподбором ширины колонок.
  • В JSON применяется кастомный сериализатор дат (ISO 8601).

Валидация
Декларативный движок валидации
# schema.yaml fields: - name: id type: integer required: true unique: true - name: email type: string required: true pattern: "^[^@]+@[^@]+\\.[^@]+$" - name: age type: integer min: 16 max: 100 - name: birth_date type: date format: "YYYY-MM-DD"

Поддерживаемые проверки:

  • required: true — не пустое и не пробельное.
  • type — integer, float, string, date, boolean.
  • min / max — числовые и календарные диапазоны.
  • pattern — регулярные выражения (RegEx).
  • unique: true — уникальность в пакете (O(1) по хеш-таблице).
  • min_length / max_length — длина строк.
  • allowed_values — допустимый список значений.

Трансформации
Трансформации данных и изоляция дефектов

7 встроенных трансформаций

  • upper / lower — регистр символов.
  • strip / trim — очистка от пробелов.
  • capitalize — капитализация первой буквы.
  • replace_map — словарь подстановок значений.
  • timestamp_to_date — Unix timestamp в дату.
  • format_date — конвертация формата дат.
  • default — значение по умолчанию при пустом поле.

Стратегия карантина (errors.csv)

Невалидные записи не блокируют весь процесс обработки:

  • Валидные данные конвертируются в целевой файл.
  • Ошибочные строки изолируются в errors.csv с сохранением всех полей, номера строки и описания ошибки.
  • Оператор может быстро исправить только ошибочные строки.

Интерфейс
Отчётность и CLI интерфейс

CLI команды утилиты

# Конвертация с валидацией и отчётом databridge convert input.csv --to json \ --config schema.yaml --output out.json \ --report report.html # Валидация файла без конвертации databridge validate input.json \ --config schema.yaml # Экспресс-анализ датасета databridge stats input.csv

Автономный HTML-отчёт

  • Метрические плашки: Всего / Успешно / Ошибок / % Качества данных.
  • Распределение ошибок по полям и правилам.
  • Интерактивный журнал строк с подробным описанием.
  • Автономность: чистый CSS без внешних CDN.
