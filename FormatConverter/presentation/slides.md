## Слайд 2: Проблема и актуальность
- **Проблема в учебных отделах и компаниях:**
  - Данные приходят в разнородных форматах (CSV, JSON, XML, Excel).
  - Человеческий фактор приводит к ошибкам: битые email, выход чисел за диапазоны, нарушение уникальности ID, несовместимые форматы дат.
  - Ручная выверка отнимает часы рабочего времени и приводит к авариям в учетных системах.
- **Целевое решение:** Консольная утилита DataBridge (CLI), автоматизирующая полный цикл обработки без необходимости разворачивать СУБД.

---

## Слайд 3: Функциональные требования (MVP)
1. **Чтение данных (4 формата):** CSV (с заголовками и без, настраиваемый разделитель), JSON (массив объектов), XML (плоская структура), Excel (.xlsx).
2. **Валидация:** Декларативные схемы (YAML / JSON) с проверками обязательности, типов, диапазонов, регулярных выражений, уникальности и длины.
3. **Конвертация:** Любой формат в любой, переименование полей (mapping), 7 встроенных трансформаций.
4. **Изоляция ошибок:** Сохранение некорректных строк в `errors.csv`.
5. **Отчётность:** Консольная сводка и визуальный HTML-отчет.

---

## Слайд 4: Архитектура системы (Pipeline Pattern)
- Применение шаблонов: **Pipeline**, **Factory Method**, **Strategy**, **Template Method**.
- Модули:
  - `readers/` — извлечение записей в единый канонический формат `List[Dict]`.
  - `validators/` — валидатор по правилам схемы с фиксацией номеров строк.
  - `converters/` — цепочка трансформаций, маппер полей, оркестратор конвейера.
  - `writers/` — экспорт в целевой формат с очисткой внутренних метаполей.
  - `reporters/` — форматирование отчетов (терминал, HTML, статистика).
- Соблюдение принципа **Open/Closed (SOLID)**.

---

## Слайд 5: Подсистема ввода/вывода (Readers & Writers)
- **BaseReader & BaseWriter:** Базовые абстрактные контракты.
- **CSV:** Автоопределение разделителя (Sniffer), устойчивость к кодировкам (UTF-8, UTF-8-BOM, CP1251).
- **JSON:** Безопасное чтение массивов и корневых объектов-оберток.
- **XML:** Чтение плоских деревьев с объединением атрибутов и дочерних узлов.
- **Excel:** Чтение ячеек и генерация стилизованных документов с автошириной колонок (`openpyxl`).

---

## Слайд 6: Движок валидации (Validation Engine)
- Схема задается в формате YAML или JSON.
- **Поддерживаемые типы валидаций:**
  - `required` (проверка на непустоту);
  - `type` (integer, float, string, date, boolean);
  - `min` / `max` (границы для чисел и календарных дат);
  - `pattern` (регулярные выражения);
  - `unique` (контроль дубликатов по $O(1)$ хэш-таблице);
  - `min_length` / `max_length` (длина текста);
  - `allowed_values` (список допустимых значений).

---

## Слайд 7: Трансформации данных и обработка ошибок
- **7 встроенных трансформаций:**
  1. `upper` / `lower` — приведение регистра;
  2. `strip` / `trim` — обрезка пробелов;
  3. `capitalize` — капитализация;
  4. `replace_map` — подстановка по словарю;
  5. `timestamp_to_date` — расчет даты из Unix timestamp;
  6. `format_date` — преобразование формата дат;
  7. `default` — заполнение пустых значений по умолчанию.
- **Стратегия изоляции ошибок (Quarantine):** Невалидные строки не блокируют корректные данные, а изолируются в `errors.csv` для быстрой ручной доработки.

---

## Слайд 8: Отчетность и интерфейс CLI
- **Консольный интерфейс:**
  - `databridge convert input.csv --to json --config schema.yaml --output out.json`
  - `databridge validate input.json --config schema.yaml --report report.html`
  - `databridge stats input.csv`
- **Автономный HTML-отчёт:**
  - Метрические карточки (Всего, Успешно, Ошибок, % Качества).
  - Аналитика по полям и правилам.
  - Детальный журнал строк без внешних зависимостей.
